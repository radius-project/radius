## AWS Support in UCP

AWS is a combination of heterogeneous services such as Kinesis, VPC, etc. Each of these services provides its own API and CLI commands which are not necessarily consistent with each other. AWS has introduced the Cloud Control API which is a wrapper on top of these services which enables users to use them with a consistent set of APIs.

In UCP, we use AWS Cloud Control APIs

With UCP, we want to support ARM-RPC protocol for clients even for systems such as AWS that do not support this protocol. While adding AWS support in UCP, we were faced with the following challenges:-
* AWS Cloud Control API has separate Create and Update operations instead of an idempotent PUT operation. The Update operation requires UCP to compute a JSON patch with the changes to be applied to the existing resource.
* AWS resources do not have a pre-defined property such as "name" that defines the resource name but is instead defined by fields that are marked as "Primary Identifiers" in the resource schema
* AWS resources can have multiple primary identifiers. In this case, the resource is uniquely identified by a combination of all primary identifiers e.g.: PrimaryIdentifierA | PrimaryIdentifierB | PrimaryIdentifierC.
* AWS resources can have generated names which means that the complete resourceID is not always known before resource creation.
* AWS has read and create only properties. This poses a challenge for computing a JSON patch for translating a PUT request to an Update AWS operation.
* Update call with no updates to the resource hangs indefinitely (operation is always in a “PENDING” state from AWS). This is currently handled by determining if the JSON patch for an update operation is empty and if empty, do not make a call to AWS and treat the operation like a no-op.

<br/><br/>

### Comparing values AWS reports in a different form

AWS often reports a value in a different form than the template set it. `GeneratePatch` (`pkg/aws/operations`) uses the type's schema, already loaded with `DescribeType`, to count these as unchanged, so an unchanged redeploy sends nothing to AWS:

- **Arrays where order does not matter.** The schema marks them `"insertionOrder": false`, such as `SubnetIds` on a DB subnet group and `Tags` on most types. They are compared ignoring order, as multisets, with each item compared by its own rules.
- **Values AWS rewrites.** The schema's `propertyTransform` turns the template's value into a pattern AWS's value must match. For example, an RDS `EngineVersion` of `8.4` matches a running `8.4.11`, and `DBInstanceIdentifier` is compared in lowercase. `$lowercase`, `$uppercase`, `$join`, `$string`, and `$OR` are supported, with string literals, array literals, and property references. A reference resolves against the property's parent object first, then the root. Text from the template is matched literally, and string literals in the expression are regular expressions. A property whose transform uses any other function or operator, or has an alternative that reads no template property (such as a fixed KMS key ARN pattern), is compared as it is, so a real change is still sent.
- **Empty objects.** An empty object AWS reports, such as `DataProtectionPolicy: {}` on a log group, is kept unless the template sets values inside it.

### Resource records and alias IDs

UCP keeps a record of each AWS resource it deploys, so redeploying a template updates the same resource. Every AWS resource in Bicep has an `alias`, and the Deployment Engine addresses the resource by it:

```text
/planes/aws/aws/accounts/{account}/regions/{region}/providers/AWS.EC2/VPC/app-vpc
```

The record (`datamodel.AWSResource`, read and written by `pkg/ucp/aws/records`) is stored in UCP's data store under that ID. It holds the AWS identifier, the owner, the properties of the last successful deploy without write-only values, fingerprints of the write-only values, and the state of the operation in progress. The design is in [radius-project/radius#13462](https://github.com/radius-project/radius/pull/13462).

- **PUT** reads the record. With no AWS identifier yet, UCP takes over a resource AWS already has, found by the top-level `name` or by the identifier in the properties, or creates one. Before it creates anything, UCP saves the record with a client token, and sends that token with every attempt to create the resource, so a retry never creates a second one. Cloud Control returns the first request only when the body matches it exactly. When a retry's template differs, for example in a write-only value, Cloud Control returns `ClientTokenConflictException` naming the first request, and UCP reads that request's status: when it succeeded, the PUT continues as an update with the template, comparing its write-only values with the fingerprints of the earlier attempt (when an earlier retry's outcome is unknown, UCP cannot tell which values AWS has, so they have no usable fingerprint); when it failed, the record is removed and the PUT returns the failure; while it runs, the PUT gets `409`. With a record, UCP compares the template with AWS and with the last-applied properties: a property the last deploy set and the template no longer sets is cleared, and a removed create-only property fails with `400`.
- **GET** reads the record, then AWS by the identifier in the record. `404` with the code `AWSResourceNoRecord` when there is no record, and `404` with `NotFound` when AWS no longer has the record's resource. The Bicep recipe driver reads the ARN of each AWS output resource with GET. On `AWSResourceNoRecord` only, it reads the resource with POST `/:get` by its ID, sent in the `X-Radius-AWS-Resource-ID` header, because a resource a recipe references with `existing` has no record and its ID ends in the AWS identifier. It never does this for an alias whose resource is gone, which could read an unrelated resource whose identifier matches the alias.
- **DELETE** reads the record, deletes the resource by its identifier, and then removes the record. `204` without calling AWS when there is no record, so a retried DELETE never deletes a different resource whose AWS identifier matches the alias.

  A record with a client token but no identifier has a create that may have reached AWS, so DELETE first sends the create again with the same token to find the resource. Cloud Control returns the original request only when the body matches it exactly. The resend has no write-only values, so for a type with write-only properties it gets `ClientTokenConflictException`, and UCP reads the status of the request it names to find the resource. When the message of `ClientTokenConflictException` has no request token UCP can read, the PUT or DELETE fails with `400` and keeps the record.
- **POST `/:get`** reads a resource Radius may not have created, for an `existing` block that sets `name` or `properties`. It reads AWS by the top-level `name` in the body when it is set, and otherwise by the primary or additional identifiers in the properties. `name` is the AWS identifier itself and is never decoded. A request with the `X-Radius-AWS-Resource-ID` header reads by the identifier in that ID's last segment instead, decoded the way UCP encoded it. The ID must be of the request's type, account, and region. A template can't set the header, so only Radius's own ID reads use it. It never saves a record.

PUT and DELETE require the `X-Radius-Resource-Owner` header, and fail with `400` without it. A PUT or DELETE from a different owner than the record's fails with `409`, and so does a PUT that would manage an AWS resource another alias's record already has. Owners are compared ignoring case.

UCP owns every create, update, and delete. It saves the new last-applied properties and fingerprints on the record as pending values before it calls AWS, saves the Cloud Control request token, and queues an operation. The backend controller in `pkg/ucp/backend/controller/awsresources` polls Cloud Control, then moves the pending values to last-applied on success, or drops them on failure so the previous ones stay. A failed create, and a finished delete, remove the record. If the worker stops after it removes the record, the redelivered operation reads its result from Cloud Control by the request token. The operation status and result routes read only UCP's data store, and return `404` for an operation UCP does not have. A second PUT or DELETE while an operation is running gets `409`. One that finds an operation nothing has polled for 10 minutes, or one AWS accepted but UCP never queued, resumes it.

Write-only values are never stored: not in the last-applied or pending properties, and not in operations. They are also removed from every response, including values AWS returns: create, update, read, `existing`, and list. A secret the schema doesn't mark write-only, such as a Cognito user pool client's `ClientSecret` that AWS generates, is only kept out of the echo of the request.

UCP has no POST `/:put` or `/:delete` routes. AWS resources deployed before records have no record, so UCP treats them like resources created outside Radius: a DELETE of their old ID returns `204` and leaves them in AWS.

### Write-only values

AWS never returns write-only values, such as passwords, so UCP cannot compare them with AWS. Instead, the record keeps an HMAC-SHA-256 fingerprint of each write-only value of the last successful deploy (`pkg/ucp/frontend/controller/awsproxy/fingerprints.go`). The key is in the `radius-aws-fingerprint-key` Kubernetes Secret, never in the data store, as described in [credentials](../architecture/credentials.md). The record stores the key ID once, apart from the digests. Each fingerprint is bound to the resource ID and the property path, and the value is encoded as JSON, so key order and number forms do not matter. A write-only property inside array items, such as `Users/*/Password`, is covered by a fingerprint of the whole array. A value in an array item AWS does not have, such as one deleted outside Radius, is always sent with the item.

| Write-only value in the template                                                                                 | What UCP does                                                                                                                                                          |
|------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Matches its fingerprint                                                                                          | Leaves it out of the update. A create-and-delete-only type succeeds without an update                                                                                  |
| Differs from its fingerprint, or the last deploy did not set it                                                  | Sends it. A create-and-delete-only type fails with `400` naming the property                                                                                           |
| No usable fingerprint: a different key made it, or UCP took the resource over and the last deploy did not set it | Sends a value that can be updated once. Does not send a value that cannot change after create, and does not fail. Either way, saves a fingerprint with the current key |

If the key is missing, unreadable, or invalid, a PUT whose template sets a write-only value fails with `500` naming the Secret, before UCP saves anything or calls Cloud Control. Other PUTs, reads, and deletes still work.

### AWS types that Cloud Control cannot fully manage

UCP returns a `400` for these AWS types instead of the error Cloud Control returns. Error messages name the type and properties, never property values.

| Type                                                                                      | How UCP knows                                                                                       | What UCP returns                                                                                                                                                                                                                       |
|-------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Legacy type with a supported replacement, for example `AWS::IAM::Policy`                  | List in `pkg/aws/awstypes`                                                                          | `400` naming the replacement, on every operation. Nothing is called in AWS                                                                                                                                                             |
| Deprecated service or CloudFormation template feature, for example `AWS::OpsWorks::Stack` | List in `pkg/aws/awstypes`                                                                          | `400` saying Radius does not support the type, on every operation. Nothing is called in AWS                                                                                                                                            |
| Read-only type created by AWS, for example `AWS::EC2::Image`                              | `DescribeType` reports `NON_PROVISIONABLE`, and the schema has a read handler but no create handler | `400` on a PUT, before UCP reads the resource, saying the type can only be used with `existing`                                                                                                                                        |
| Other type Cloud Control cannot create, with no native handler                            | `DescribeType` reports `NON_PROVISIONABLE`                                                          | `400` on a PUT, before UCP reads the resource. A type with a native handler is served by it instead, as described in [Native handlers](#native-handlers)                                                                               |
| Create-and-delete-only type                                                               | `DescribeType` reports `IMMUTABLE`                                                                  | Create works. A change to an existing resource fails with `400` naming the changed properties. A write-only value counts as changed only when it differs from its fingerprint, as described in [Write-only values](#write-only-values) |

UCP reads the provisioning type from CloudFormation at run time, so a type starts working without a Radius release when AWS adds Cloud Control support for it.

The read-only list in `pkg/aws/awstypes` is for callers that have no AWS access, such as the recipe engine. It is generated from a snapshot of the CloudFormation registry. To refresh it with AWS credentials, run `go run ./gen -refresh` from `pkg/aws/awstypes`.

### Extra read-only properties

Some values a recipe needs are not in the Cloud Control schema, so Cloud Control never returns them. For the types listed in `pkg/aws/extraproperties/extra_properties.json`, UCP makes one more AWS call when it reads a resource and adds each value as a read-only property. The Bicep type generator reads the same file, so the Bicep types match what UCP returns.

| Type                          | AWS call                    | Extra properties                                                                                                                        |
|-------------------------------|-----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------|
| `AWS::MSK::Cluster`           | `kafka:GetBootstrapBrokers` | Every broker address field AWS returns, such as `BootstrapBrokerString`, `BootstrapBrokerStringTls`, and `BootstrapBrokerStringSaslIam` |
| `AWS::MSK::ServerlessCluster` | `kafka:GetBootstrapBrokers` | `BootstrapBrokerStringSaslIam` and `BootstrapBrokerStringSaslIamIpv6`                                                                   |

- Only a GET and a POST `/:get` make the extra call. A list does not, and create, update, and delete still use Cloud Control only.
- A field AWS leaves empty, because the cluster doesn't use that access method, is left out.
- UCP adds the values only to its response. A PUT that sets one drops it before comparing, so it is never sent to AWS or stored in the record.
- If AWS adds a property with the same name to the type's schema, AWS's property wins: a read returns Cloud Control's value, and a PUT sends it to AWS like any other property.
- If the extra call fails, such as for a missing `kafka:GetBootstrapBrokers` permission or a cluster that is not active yet, the read fails with AWS's error code and message, naming the call. The status follows the rule for every AWS error in UCP: `400` when AWS reports a client fault, such as access denied or throttling, and `500` otherwise. UCP never leaves the values out silently.

### Native handlers

A native handler serves an AWS type by calling the service's own API through the AWS SDK, for types Cloud Control can't create in a region and types with no CloudFormation type. The interface and registry are in `pkg/ucp/aws/native`, and `pkg/ucp/aws/native/handlers` lists the handlers UCP registers. Each handler's schema, in CloudFormation format, is in `pkg/aws/schemas`: `native/` for types that have a CloudFormation type, and `handwritten/` for types that don't.

UCP picks the handler for each request:

1. A hand-written type always uses its native handler. UCP never asks CloudFormation about it.
2. A type in `native/` uses its native handler only when `DescribeType` reports it `NON_PROVISIONABLE` in the request's region. Otherwise Cloud Control serves it. `DescribeType` results are cached for 15 minutes, so a region that gains Cloud Control support switches without a release. If `DescribeType` fails, the request fails with that error.
3. Every other type uses Cloud Control.

Both handlers use the same record. The native schema replaces CloudFormation's with either handler, so both store the same AWS identifier, use the same property names, and treat the same properties as write-only. Every secret is write-only in the native schema, including ones CloudFormation's doesn't mark, and UCP removes write-only values from what either handler returns, because some service APIs return secrets. The record saves which handler started an operation (`handler`), and that handler finishes it, even if the region has since switched.

When AWS lets the caller choose the name and the template leaves it out, a handler declares the name property (`NameProperty`), and UCP generates `radius-` followed by 12 lowercase hex characters of a SHA-256 hash of the record's client token, such as `radius-3f9a1c0b7d2e`, cut to the property's `maxLength` in the schema. A name that doesn't fit the property's `minLength` or `pattern` fails the PUT with `400` before UCP calls AWS, asking for the name in the template. The client token identifies the create, so every retry of one create sends the same name. UCP saves the name on the record before it calls AWS, and leaves it out of the last-applied properties, so a later deploy that still leaves it out doesn't clear it. The property stays optional, because Cloud Control names the resource itself where it serves the type.

Each handler declares how UCP finds a create it lost after AWS accepted it (`Recovery`). A PUT, and a DELETE of a record whose create may have reached AWS, take the same steps:

| `Recovery`            | When                                                                                              | How UCP finds the resource                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
|-----------------------|---------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `RecoverByIdentifier` | The identifier is known before the create, because the template sets it or UCP generates it       | UCP saves the identifier on the record before the create and reads AWS by it. A create whose template doesn't give the identifier fails with `400` before UCP calls AWS                                                                                                                                                                                                                                                                                                      |
| `RecoverByResend`     | AWS assigns the identifier, and the API takes an idempotency token, or the call is safe to repeat | UCP sends the create again with the record's client token, which the handler passes as the token, so AWS returns the first resource. Two requests can resend at once, so `Create` with the same client token must return the same resource every time and never create a second one. That resource may have the first attempt's values, so UCP reads it and updates it to the template, sending every write-only value. Before a delete, the resend has no write-only values |
| `RecoverBySearch`     | AWS assigns the identifier, and the API takes no token                                            | The handler tags the create with the client token, or relies on values AWS keeps unique, and its `Find` looks for the resource with the first attempt's values, without write-only values, because the template may have changed. UCP sends the create again only when AWS has none, and returns `409` when another alias manages the resource `Find` returns                                                                                                                |

Once UCP has the identifier, it reads AWS: if AWS has no resource, a PUT creates it and a DELETE removes only the record; if AWS is still creating it, UCP waits for it and returns `409`; otherwise the PUT continues as an update and the DELETE deletes it.

A native operation follows the same steps as a Cloud Control one: owner check, compare, save pending values, start call, operation status. The handler's start call returns at once, UCP makes its own operation ID, and the worker calls the handler's `Progress` until the operation finishes or the handler's timeout passes. `Progress` only reads AWS, so a restarted worker waits again safely. UCP queues native operations under their own operation type, `AWSRESOURCENATIVE`, so a worker that finds the record already removed never asks Cloud Control about them.

A handler whose identifier isn't its primary identifier values joined with `|` declares its own encoding. UCP uses it for create, take-over, `existing`, recovery, and delete, with either handler. The identifier stays exactly what AWS uses, such as an S3 ARN with `/`. Only the resource ID that a list or `existing` returns for a type with a native handler escapes it into one segment, with URL path escaping. POST `/:get` decodes that segment only when the ID comes in the `X-Radius-AWS-Resource-ID` header, so a recipe reads the resource again by its ID, and a literal `name` such as `a%2Fb` is never decoded.

| Scenario                                                                       | What UCP does                                                                                                                                                                                                                                                     |
|--------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| AWS rejects the start call                                                     | `400` with AWS's message. Pending values are dropped. A rejected first create removes the record                                                                                                                                                                  |
| The start call fails with a server or transport error, or partway              | An update's pending values count as possibly applied, as in the outcomes table below. A create keeps its client token and identifier                                                                                                                              |
| A first create was interrupted                                                 | The next PUT or DELETE finds the resource as the handler's `Recovery` says, as described above                                                                                                                                                                    |
| Finding a lost create fails, such as a failed `Find` or a rejected resend      | The PUT or DELETE fails with AWS's error and keeps the record, so the next request tries again. A `Find` that matches more than one resource fails naming them, and UCP adopts and deletes none                                                                   |
| The operation fails in AWS                                                     | The operation fails with the handler's message, and the pending values are set by its outcome. A failed create keeps the record, because the resource may exist                                                                                                   |
| Waiting passes the handler's timeout                                           | The operation fails, naming the state UCP waited for. The next deploy reads the resource and continues                                                                                                                                                            |
| The type can't be listed, or only under a parent                               | `400` on a list                                                                                                                                                                                                                                                   |
| The identifier names another product, such as an Aurora cluster for DocumentDB | A PUT, GET, or `existing` gets `409` naming the identifier, and UCP changes nothing. A DELETE treats it as not found: the resource the alias managed is gone, so UCP removes only the record and never touches the other product's resource. A list leaves it out |

A failed native operation is sorted into one of four outcomes (`native.Outcome`), which set the record's pending values (`records.Settle`). A handler reports the outcome with a `native.Failure`, from its start call or from `Progress`. Any other start call error is rejected for an AWS client fault or a resource of another product, and unknown otherwise. A start call that fails fully applied finishes the operation: a create whose identifier UCP has is done, and a delete or reset removes the record:

| Outcome                                                                               | What UCP does with the pending values                                                                                                         |
|---------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| Rejected before any change                                                            | Drops them, as if nothing happened                                                                                                            |
| Partly applied, such as an operation that makes several calls failing after the first | Keeps them as possibly applied, so a later deploy that removes one clears it. The next deploy reads AWS and makes only the calls still needed |
| Unknown, because UCP stopped before it saw the result, or the handler doesn't say     | The same as partly applied                                                                                                                    |
| Fully applied, but the operation still failed                                         | Moves them to last-applied. A fully applied delete removes the record                                                                         |

When a later deploy finds the resource of an interrupted create, the values of that create also count as possibly applied.

Each handler also declares:

- **Values AWS returns in another form**, such as an engine version `5.0` that comes back as `5.0.0`, so they don't count as changes. The native schema's `propertyTransform` covers what it can, as for Cloud Control types (see [Comparing values AWS reports in a different form](#comparing-values-aws-reports-in-a-different-form)). Otherwise the handler sets `Options.Equivalent`.
- **A filter when the service API also serves other products**, such as DocumentDB's API returning Aurora clusters. The handler checks the product before every read, update, delete, and reset, and returns `native.OtherProductError` for another product. A PUT, GET, or `existing` gets `409` naming the identifier, and UCP changes nothing. A DELETE removes only the record, so deleting an app is never blocked, and the other product's resource stays as it is.

#### Per-type metadata

CloudFormation's schema format has no field for some things UCP needs to know about a type, so a type can have a metadata file next to its schema in `pkg/aws/schemas`, named after the schema with `.metadata.json` in place of `.json`, such as `aws-iam-accountpasswordpolicy.metadata.json`:

```json
{
  "typeName": "AWS::IAM::AccountPasswordPolicy",
  "identityScope": "account",
  "onDelete": "reset",
  "arnProperty": ""
}
```

| Field           | Values                                                       | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|-----------------|--------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `identityScope` | `region` (default) or `account`                              | How far an identifier reaches. Before UCP takes over or creates a resource, it searches this scope for another alias that holds the identifier, and returns `409` naming it. For `account`, that includes an alias in another region, so two regions never manage the same account-wide setting. The search and the save that follows are separate steps, so two aliases that take over the same identifier at the same moment can both succeed                                                                                                                                                                                                                                                                                                            |
| `onDelete`      | `delete` (default), `reset`, `nothing`, `reject`, or `leave` | What a DELETE does. `delete` deletes the resource in AWS and removes the record. `reset` calls the handler's `Reset` (`native.Resetter`), which sets the resource back to AWS's default, and removes the record; where Cloud Control serves the type, Cloud Control deletes it. `nothing` calls nothing in AWS and removes the record. `leave` calls nothing in AWS and keeps the record, as for a purchase, so a later deploy of the alias finds it and buys nothing. `reject` returns `400` and changes nothing when AWS has the resource, and removes the record when it doesn't. A record whose create may have reached AWS finds the resource first, but never by sending the create again: a create only a resend could find removes only the record |
| `arnProperty`   | A property name, or `""` for none                            | The property that holds the resource's ARN, which recipes save on their output resources. It overrides the generated catalog in `pkg/aws/arnproperties`, which has no hand-written types                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

UCP applies the metadata with either handler. A file that names another type, has no schema next to it, or has an unknown field or value fails when UCP loads the schemas, and the registry fails for a `reset` type whose handler has no `Reset`.

#### More handler declarations

- **A delete token** (`native.DeletePreparer`), for a delete that takes a copy of the data, such as a DocumentDB cluster's final snapshot or an FSx file system's final backup. Before the first delete call, UCP saves the handler's token on the record (`deleteToken`), such as the snapshot name, and sends the same token on every attempt, so a retried delete never takes a second copy. A create or update clears it, and so does a delete AWS reports as failed.
- **Members of a parent** (`native.ScopedReader` and `native.ScopedDeleter`), for a type whose resource is some members of a parent that others can add to as well, such as users added to an existing IAM group. UCP gives the handler the property sets the alias may have applied, and the handler reads and removes only those members, so members added outside Radius stay through a take-over, an update, and a delete. An update removes members first, and a failure while removing is reported as rejected, so the record keeps every member it may still have to remove. An update that UCP stopped before it saw the result keeps the members of both the last deploy and that update, so the next deploy removes the old ones. A lost create that UCP sends again with a changed template keeps the members of both templates, so a delete removes them all. A template that changes the lost create's parent, or another create-only property, gets `400`, and nothing is sent.

UCP also checks the native schema's create-only properties before it calls a native handler, and returns `400` naming the ones a template changed, because a service API may ignore such a change where Cloud Control rejects it. A first create that failed with nothing applied in AWS (`native.OutcomeRejected`), such as an AppSync schema that didn't parse, is sent again by the next deploy with that deploy's template.

#### Testing native handlers

Every native handler runs the shared suite in `pkg/ucp/aws/native/nativetest`, which deploys through UCP's controllers and worker with an in-memory AWS. A handler's tests give it a fake of the service's API backed by the same in-memory store. `pkg/ucp/aws/native/nativefake` has a fake handler for testing the framework. `Test_SchemaPermissionsCoverAWSCalls` in `pkg/ucp/aws/native/handlers` reads each handler's source and fails when a handler makes an AWS call that its schema's handler permissions don't list for the operation that makes it.

Each handler also has a `Test_Replay_*` test that runs a create, read, update, and delete through the real AWS SDK against AWS's recorded responses (`pkg/ucp/aws/native/awsreplay`), in `testdata/` next to the handler. A cassette's `source` says whether AWS's responses were recorded or written by hand from the AWS API reference, for a type the recording account can't create. To record one:

1. Create the supporting resources the test reads with `session.Input`, such as a subnet, and export their IDs as the `RADIUS_REC_*` variables the test names. Tag everything you create, and delete it afterwards.
2. Run the test with AWS credentials and `RADIUS_AWS_RECORD=1`, such as `RADIUS_AWS_RECORD=1 go test -count=1 -timeout 2h -run Test_Replay ./pkg/ucp/aws/native/handlers/docdb/`. Region is always us-west-2. If the test fails after the create, it deletes the resource it created in cleanup and waits for AWS to finish, or says which one to delete by hand.
3. Check the cassette before committing it. Recording keeps no request or response headers except the few the SDK needs, replaces the account ID with `123456789012`, and replaces each value the test registers with `session.Scrub` with `x` characters, but grep the file for your account ID and any secret anyway. Format it with Prettier, because `make format-check` checks every JSON file.
